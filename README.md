# 厉鬼模块化

> 《神秘复苏》的非官方附属。把厉鬼装进你手上的任何东西，也可能在地里撞见它们。

模组依赖本体 [神秘复苏](https://gitee.com/xiaoxieY/mysterious-revival)，本体需为 **1.5.0 / Fabric 1.20.1**。
本模组不包含本体的任何代码与素材。

---

## 它做了什么

三件事，可以分开玩，也可以串起来：

| | 一句话 |
|---|---|
| **万物融合** | 把厉鬼融进任何物品，物品获得它的技能、被动与灵异伤害 |
| **灵异交错** | 一只鬼会借用别的鬼的杀人规律 —— 同一只鬼可能有六种杀你的理由 |
| **鬼方块** | 地里可能埋着一只被钉住的鬼，外观和周围方块一模一样 |

---

## 安装

1. Fabric Loader 0.14+ / Minecraft 1.20.1
2. 本体 **神秘复苏 1.5.0**（必需，否则无法启动）
3. 把本模组的 jar 放进 `mods/`

> 卸载本模组不会损坏本体存档；已融合的物品会变成普通物品（附加数据留在 NBT 里）。

## 万物融合

从灵异主界面右侧进入「装置」，左槽放物品、右槽放厉鬼。

**什么都能装**：剑、镐、盾牌、木棍、锄头 —— 没有任何物品限制。

融进去之后拿到三样东西：

| 能力 | 说明 |
|---|---|
| **技能** | 按 `X` 打开面板，手上拿的是什么就只看什么的技能 |
| **被动** | 放在背包里就生效，不占鬼槽、不需要手持 |
| **灵异伤害** | 打鬼才有意义 —— 原版攻击对鬼无效，这份伤害才掉它的灵异强度 |

### 成本

```
压制值 = 灵异强度 + 灵异抗性 + 灵异伤害 × 0.5
需求值 = (入门费 + 各模块代价) × 30 × (1 + 0.75 × 已有鬼数)
```

- 压制够 → 直接成功
- 压制不够 → 让你赌一把，赢了规律照样进，输了挨反噬

**反噬四件套**：灵异强度、血量、鬼槽复苏度，外加素材鬼被消耗。
所以这不是免费加强，是拿鬼换武器。

### 失败时鬼会跑

赌输之后掷一次「复苏」：

| 连续失败 | 复苏概率 |
|---|---|
| 第 1 次 | 5% |
| 第 2 次 | 15% |
| 第 3 次 | 25% |
| … | 每失败一次 +10% |

成功一次立刻清零。复苏的鬼会当场从容器里爬出来，就站在你脚下。

### 灵异伤害公式

```
基础灵异伤害 = Σ(每只鬼的最大灵异 × 10%)
继承倍率     = 鬼数 × 50%
实际伤害     = 基础灵异伤害 + 玩家灵异伤害 × 继承倍率
```

融三只高数值的鬼约 700+ 基础，比本体最强的灵异武器还高一截。

## 灵异交错

新世界生成的厉鬼，会**借用别的鬼的规律**：

| 难度 | 借规律 | 借机制 |
|---|---|---|
| 和平 | 0 | 0 |
| 简单 | 2 | 0 |
| 普通 | 3 | 1 |
| 困难 | 4 | 2 |

也就是说困难难度的一只鬼，可能有 **6 种杀你的理由**。

### 借的是两种东西

**① 规律（零适配）**

运行时造一只「影子」实例，直接调用它的 `shouldAttackPlayer` —— 用的是本体自己的代码。
所以任何继承了 `GhostEntity` 的鬼（包括别的附属的）都会自动参与，不需要写一行适配代码。

**② 机制（我们重写）**

本体没有「可复用的行为单元」，43 只鬼的行为都写在各自的类里。所以挑出那些**只读玩家状态**的机制，重写成能挂任意宿主的模块 —— 目前 **22 个**：

```
背对 / 抬头 / 埋头 / 直视      视线与朝向
潜行 / 静止 / 移动             姿态与运动
涉水 / 暗处 / 庄稼 / 踩踏      地形与环境
携矿 / 裸甲 / 进食 / 染疫      背包与状态
开箱 / 着火 / 跳跃             交互与状态
拾荒 / 无钱                    世界状态
空间压制 / 域在场              鬼域
```

做不到的那批（门鬼、方块鬼的组合判定、警官的域配额）没有硬做 —— 装上也永远不触发，比不做更糟。

### 出手节奏

交错两次袭击之间至少 **5 秒**，与本体一致。

> 本体每只鬼的冷却写在它自己的 `shouldAttackPlayer` 里，而交错的允许是短路返回的 —— 不自己补一道闸，就会出现「一秒打二十下」。

## 鬼方块

某些方块下面可能藏着鬼。**它长得和周围一模一样**：平原是草方块，地底是原石，山上是石头。看不出任何区别。

- 靠近 **10 格**：听到一声遇鬼音（每 10 秒一次）
- 每 **5 秒**：按里面那只鬼的规律判定你一次
- 判定通过：只吃 **10% 灵异伤害**（走本体的 `handleSpiritDamage`，灵异抗性照常生效）
- 被判定命中 **10 次**，或者方块被打破 → 鬼爬出来

判定不通过时你不会知道刚才差点死。

### 野外布置

世界**第一次**被本模组接管时，在出生点附近布置 8 个（半径 256 格，位置由世界种子决定）。之后默认不再增加。

想「边探索边偶遇」：把 `haunt.newChunkChance` 调到 `0.02`。单世界总量有硬上限 `haunt.maxTotal`（默认 128），到顶就停 —— 防止存档数据随探索无限增长。

### 手动制造

```bash
/ghostmodules haunt smfs:door_ghost     # 把看着的方块变成鬼方块
/ghostmodules haunts                    # 看附近有哪些（坐标/鬼种/复苏/距离）
```

## 卡卡罗特

一只会变身的彩蛋鬼。

- 召唤 / 融合后按 `R` → 金发、气焰、**灵异伤害 ×50**，代价是持续烧复苏度
- 按 `C` → 龟派气功
- 去掉了鬼域，只保留变身

## 按键

独立分类「厉鬼模块化」，不与本体混在一起：

| 默认键 | 功能 |
|---|---|
| `X` | 灵异技能面板 |
| `R` | 超赛变身 |
| `C` | 龟派气功 |
| **未绑定** | 打开配置界面（自己去按键设置里分配） |

## 命令

```bash
/ghostmodules check            质量检测：规则总数、停用、白借的交错
/ghostmodules list             最近的鬼有哪些模块
/ghostmodules rules            最近的鬼的规则（优先级/代价/互斥组）
/ghostmodules attach <模块>     给最近的鬼手动挂载
/ghostmodules detach <模块>     卸载
/ghostmodules cross [force]    给最近的鬼补上/重抽交错
/ghostmodules spawn <实体ID>    就地生成一只鬼（按当前难度自动交错）
/ghostmodules haunt <实体ID>    把看着的方块变成鬼方块
/ghostmodules haunts [范围]    列出附近的鬼方块
/ghostmodules assembly         当前装配表
/ghostmodules slots            鬼槽 API 视角（含融合物品投影）
```

## 配置

首次启动生成 `config/smfsaddon.json`；也可以在**创建世界界面 →「厉鬼模块化配置」**里用加减按钮调，保存即时生效。

| 项 | 默认 | 说明 |
|---|---|---|
| `crossing.easyRules` / `normalRules` / `hardRules` | 2 / 3 / 4 | 各难度借几条规律 |
| `crossing.normalMechanisms` / `hardMechanisms` | 1 / 2 | 各难度借几个机制 |
| `crossing.allowCooldownTicks` | 40 | 交错出手间隔，调大更温和 |
| `fusion.stealRatio` | 0.10 | 每只鬼贡献最大灵异的比例 |
| `fusion.inheritPerGhost` | 0.50 | 每只鬼增加的继承倍率 |
| `fusion.entryCost` / `costScale` | 50 / 30 | 融合需求 |
| `escape.enabled` | true | 关掉后融合失败不会复苏厉鬼 |
| `escape.baseChance` / `stepChance` | 0.05 / 0.10 | 复苏概率与每次失败的叠加 |
| `haunt.enabled` | true | 鬼方块总开关 |
| `haunt.triggerRadius` | 10 | 判定半径 |
| `haunt.initialCount` / `initialRadius` | 8 / 256 | 世界初始布置 |
| `haunt.newChunkChance` / `maxTotal` | 0 / 128 | 新区块生成概率与总量上限 |

觉得太难：`hardRules` 调 3、`allowCooldownTicks` 调 60。
觉得太简单：反过来。

> 数值在加载时会被夹回安全区间，手改坏了也不会崩 —— 文件会被自动修正成实际生效的值。

## 联机与服务器

**只能用「内嵌服务器」联机**：主机在自己的存档里开「对局域网开放」，或用 Essential / 联机工具。玩家都装上本体与本模组即可。

**独立服务器（dedicated server）暂时不行**，原因不在本模组 —— 本体 1.5.0 的 `ModNetwork.register` 在服务端初始化时引用了 `net.minecraft.client.gui.screen.Screen`，服务端环境加载该类直接抛异常：

```
java.lang.RuntimeException: Cannot load class net.minecraft.client.gui.screen.Screen in environment type SERVER
    at com.xie.smfs.network.ModNetwork.register(ModNetwork.java:627)
```

所以只要本体没能上服务端，任何附属都上不去。等本体修好这一处，本模组不需要改。

## 构建

```bash
./gradlew remapJar
```

产物在 `build/libs/`。需要把本体 `smfs-1.5.0.jar` 放到 `libs/` 下（不入库，体积太大）。

## 已知限制

- 交错只对**新生成**的鬼生效；老存档里已有的鬼可用 `cross` 补
- 鬼域类机制（警官的配额、块鬼的组合判定）没有做成可借模块
- 融合物品不提供理智上限 —— 这是刻意的代价，不是遗漏
