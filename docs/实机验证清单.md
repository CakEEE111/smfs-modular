# 实机验证清单

> 目标是确认四件事真的在工作：**图鉴记录、协同解锁、装配变体、非实体宿主**。
> 全程大约 5 分钟，按顺序做，每步都有「应该看到什么」和「没看到说明什么」。

前置：装好 mod，进一个**允许作弊**的创造模式世界。

---

## 0. 开服前的一眼（30 秒）

进世界后立刻看日志：

```
装配表已载入 1 条鬼类型配置（来自 1 个文件）
```

**没看到** → 装配表没载入。检查 `data/smfsaddon/ghost_assembly/qiaomen_ghost.json` 是否在包内，
或数据包解析是否报错（日志里搜 `smfsaddon/assembly`）。

然后敲：

```
/ghostmodules assembly
```

**应该看到**：

```
=== 厉鬼装配表 ===
smfs:qiaomen_ghost
  · 只敲门 ×4  [smfsaddon:step_ghost]
  · 拼完整 ×1  [smfsaddon:step_ghost, smfsaddon:domain_presence]
```

**命令不存在** → `SmfsAddon.onInitialize` 提前返回了，看日志里有没有
`本体尚未初始化，内容注册已挂起` 之后再无 `卡卡罗特鬼加载完成`。

## 1. 图鉴记录（1 分钟）

```
/summon smfs:qiaomen_ghost
/ghostmodules attach smfsaddon:spatial_pressure
```

站到鬼 **6 格以内**，原地等 10 秒，然后：

```
/ghostcodex
```

**应该看到**：

```
===== 厉鬼规律图鉴 =====
敲门鬼 (smfs:qiaomen_ghost)
  · 无形压迫 ×N
    ？？？（再观察 N-M 次）
```

再等十几秒，`×3` 之后描述那一行会从 `？？？` 变成正式文字。

**空图鉴** → 记录没发生。可能原因：站太远（规则只在 6 格内扫描）、
或 `PlayerEvents` 写回失败（看日志有没有 `Failed to record codex observation`）。

**有条目但次数不涨** → 节流挡住了。同一组合每 40 tick 才记一次，属正常。

## 2. 协同解锁（1 分钟）

```
/ghostmodules attach smfsaddon:step_ghost
/ghostmodules attach smfsaddon:domain_presence
```

（同一个鬼上挂两个模块）

```
/ghostmodules list
```

**应该看到 3 个模块**——多出来的是 `smfsaddon:cornered`，它是自动挂上的。

然后站到这只鬼的**上方**、3 格以内。

| 结果 | 说明 |
|---|---|
| 它开始打你 | 协同生效（原本你站高处是安全的） |
| 它够不到你 | 协同没触发，检查 `list` 里有没有 cornered |
| 有 cornered 但没生效 | 裁决链路问题，试 `/ghostmodules rules` 看 `cornered/point_blank` 是否存在 |

对照组：把鬼身上的 `domain_presence` 卸掉，再站上方，它应该就打不到了。

## 3. 装配与变体（1 分半，这条最重要）

```
/summon smfs:qiaomen_ghost
```
连刷 5 只，逐只靠近后：

```
/ghostmodules list
```

**应该看到模块数不一致**：大多数是 1 个（`step_ghost`），偶尔是 3 个
（多出 `domain_presence` 与 `cornered`）——这就是 4:1 权重在起作用。

如果没有装配表覆盖（`/ghostmodules assembly` 为空），新刷的鬼**应该一个模块都没有**。

### 持久化验证（关键）

1. 记住某只鬼的模块数（比如 3 个）
2. 退出世界再进
3. 找到同一只鬼，`/ghostmodules list`

**必须还是 3 个**。如果变了 → NBT 里 `SmfsAddonVariant` 没写进去或没读回来。

这一步比随机本身更重要：**抽中即固定**是这套东西能被称为"规律"的前提。
如果每进一次世界就重抽，玩家学到的规律全都会失效。

## 4. 非实体宿主（1 分钟）

```
/give @s smfsaddon:ghost_lantern
```

拿在手上看 tooltip，**应该显示**：

```
它被谁摸过，自己记得。
承载规律：1 条
```

拿着它原地站约 **10 秒**（复苏值涨到 100），**应该开始被缓慢**并听到监守者心跳声。

> 现在每次扫描 +5 点，10 秒到阈值。早先设成 +2（25 秒），实测时太容易被当成「没反应」。

**看不清有没有触发**时，用诊断命令：

```
/ghostmodules held
```

会打印模块列表、当前复苏值 / 上限、是否到阈值。这是判断「模块没挂上」「挂了但没涨」
「涨了但效果没出来」的唯一可靠方式。

> 注意：**创造模式飞行时缓慢是看不出来的**。要验证效果请切生存、站在地上走两步。

**tooltip 显示「承载规律：无」** → 物品宿主的 `inventoryTick` 没跑起来，
或首次装配失败（看日志 `装配失败`）。

## 症状对照表

| 症状 | 大概率原因 |
|---|---|
| `/ghostmodules` 命令不存在 | 入口提前返回 / 命令注册在 return 之后 |
| 图鉴一直空 | 站太远；或 `setSpiritAttributes` 没写回 |
| 图鉴次数涨得极慢 | 正常节流（40 tick） |
| 协同不出现 | 所需模块没同时挂上；或 `syncCombos` 没被调用 |
| 装配没生效但表有内容 | 实体类型 ID 写错（要写 `smfs:xxx` 全名） |
| 重进世界后变体变了 | `SmfsAddonVariant` 未持久化 |
| 方块/物品上挂了鬼模块没被拒 | 能力判定有洞，这是 bug |
| 鬼灯笼 tooltip 显示「承载规律：无」 | `flush` 只看 dirty 标志导致没写进 NBT（已修）；或客户端没 `syncState` |
| 鬼灯笼挂了模块但站久了没反应 | 复苏值没持久化，每次 `open()` 从空 NBT 重建（已修） |
| 启动就崩在 Mixin | 本体版本或映射变了，对照文档第 8 节核对四个方法名 |

## 目前无法验证的

- **方块宿主挂鬼模块被拒绝**：`/ghostmodules attach` 只找最近的鬼，
  没有面向方块的入口。要看这条得自己加个命令或看日志。
- **能力（GhostAbility）**：`useAbility` 没有任何调用方，也没有键位，
  现在只是个 API。
